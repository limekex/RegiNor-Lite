# 0.1.23 – bekreftet kursstart før kursperioden

Testutgave 25. september 2026. Et introkurs kan legges før den vanlige kursperioden uten å flytte oppstarten for de andre kursene.

## Slik brukes det

1. Åpne kursets oppsett eller LetsReg-importen, og åpne **Kursfrie dager og flere valg**.
2. Velg dato i **En annen første kursdato (valgfritt)**.
3. Kryss aktivt av **Tillat kursstart før kursperioden**. Avkryssingen er av som standard; et datoforslag fra LetsReg gir ikke automatisk tillatelse.
4. For et enkelt introkurs: sett **Antall undervisningskvelder** til **1**, med riktig ukedag og start-/sluttid.
5. Forhåndsvis, kontroller den faktiske datoen og bekreft lagringen/importen.

Unntaket vises i forhåndsvisningen og publiseringskontrollen. Tillatelsen lagres bare på dette kurset, med eksisterende endringshistorikk. Fjerner du avkryssingen mens datoen fortsatt er før perioden, forklarer kontrollen hva som må endres. Kopiering til ny periode nullstiller både første dato og tillatelsen.

## Datogrenser og visning

- Både skjema og server krever den manuelle bekreftelsen. Det gjelder også import.
- Økter og kursfrie dager for dette kurset kan ligge fra den godkjente første datoen. Tidligere flytting krever en ny første dato. Felles kursfrie dager følger fortsatt periodens grenser.
- Periodens sluttdato, kursets eventuelle absolutte sluttdato, ukedag, kollisjoner og vern av historiske økter gjelder fortsatt.
- Synlighets- og påmeldingsvindu flyttes ikke. Kontroller **Synlig fra** hvis introkurset skal vises før den vanlige perioden; ved manuell påmeldingsstatus må salgsvinduet også passe.
- Kurskort, kursprofil, schema og kalenderfil bruker faktiske kursøkter. Ukeskalenderen viser en datomerknad for tidligere oppstart. Offentlig valg av gjeldende/kommende periode følger fortsatt første og siste faktiske økt.
- TECs samleoppføring følger fortsatt kursperiodens oppgitte start/slutt. Unntaket oppretter ikke et eget TEC-arrangement.

Ingen eksisterende data migreres, og ingen produksjonsinnstillinger er endret. Tidspunkt/tillegg av kurs følger fortsatt vanlig kladd-, forhåndsvisnings- og publiseringsflyt.

## Verifikasjon

Nye regresjonsprøver dekker manglende/avslått godkjenning, tidligere enkeltøkt, lagring, fjerning av avkryssing, kopiering, dato-/ukedagsgrenser, kollisjon, publisering, LetsReg-import og faktiske datoer i kalender/schema. DOM-prøven gjenskapte blokkeringen før rettingen.

- `npm run test:admin`: 117 kontroller består, inkludert datoavkryssing, kopiering, kollisjoner, publisering, schema og kalenderfil.
- `npm run test:storage`: 65; `npm run test:workflow`: 92; `npm run test:http`: 43 – består.
- `npm run test:public`: 99; `npm run test:public-http`: 83 – består.
- `npm run test:letsreg-import`: 117 kontroller med syntetiske API-svar – består. Ingen eksterne kall er sendt.
- `npm run test:calendar`: 43; `npm run test:wordpress` – består.
- `npm run test:interface`: DOM-/skjemaprøver består, med ny kontroll av avkryssing og dato-/fridagsgrenser.
- `composer check`: 230 tester / 565 assertions og syntakskontroll består.
- Testene har ryddet sine syntetiske data.
- POT-generering, pakking og `git diff --check` består. Alle 126 runtime-filer i ZIP-en samsvarer byte for byte med kildefilene; ZIP-integriteten er kontrollert.

Faktisk Avada-/produksjonsprøve og import fra live LetsReg er ikke utført her. Kapasitets-, målings- og TEC-integrasjonsprøver er ikke kjørt på nytt; disse integrasjonene er ikke endret.
