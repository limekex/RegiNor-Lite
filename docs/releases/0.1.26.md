# 0.1.26 – rikere kalenderinnhold

Testutgave 26. september 2026.

- Kalenderoppføringene får fullt kursnavn, nivå uten dobbeltføring og «Kurskveld X av Y».
- Kalendernavnet inkluderer nettstedets navn, kurs med nivå og kursperiode.
- Kort beskrivelse, nivå/forkunnskaper, aktuell instruktør når oppgitt og synlig kurslenke legges i beskrivelsen. Hvert tekstutdrag begrenses til 400 tegn pluss ellipsetegn. HTML omformes til ren tekst.
- Aktive kvelder nummereres kronologisk over hele kurset, også gjennomførte kvelder. Individuelt avlyste og fjernede kvelder beholdes uten nummer, med samme UID. Kursfri teller ikke. Flytting kan endre nummerering, men ikke identitet. Avlysning av hele kurset beholder nummereringen av planlagte kvelder.
- Nedlasting og abonnement bruker samme innhold. Tid, sted, avviksgrunn, stabile identiteter og endringsversjoner beholdes. Kapasitet og kjøpspåstander inngår ikke.
- Parberegningen er uendret og kontrollert: 7 førerplasser og 7 følgerplasser gir 7 par (14 deltakere). Samlet ledighet på 7 deltakere begrenser dette til 3 par.

Eksisterende abonnement får innholdet ved neste vellykkede henting. Tidligere nedlastede kopier oppdateres ikke automatisk. Ingen produksjonsendringer eller live API-kall er utført. Faktiske abonnementsklienter og deres håndtering av kalendernavn/oppdateringer må fortsatt prøves.

## Verifikasjon

- `composer check`: syntakskontroll og 231 tester / 575 assertions består, inkludert par-eksemplene.
- `npm run test:calendar`: 56 kontroller består, inkludert HTML til tekst, nivå uten dobbeltføring, tekstlengde, instruktør, nummerering, avlysninger, UID/revisjon og synlighet.
- `npm run test:calendar-http`: 28 kontroller består med uavhengig ICS-parser (icalendar 7.3.0), faktiske lokale HTTP-svar, nedlasting/feed, flytting og avlysning.
- `npm run test:storage`: 65; `npm run test:public`: 119; `npm run test:public-http`: 83 – består. `npm run test:interface` består.
- Den første kalenderkjøringen avdekket et manglende påkrevd felt i den nye nivå-testfixturen. Dette er rettet og prøven kjørt på nytt. HTTP-testens manglende Python-parser ble installert i et isolert midlertidig miljø før vellykket kjøring.
- Testobjekter ryddet. POT oppdatert. Ingen live API-/produksjonsprøve, manuell kalenderklientprøve eller ny samlet TEC-/rolle-/målingstest er gjennomført i denne kalenderleveransen.
