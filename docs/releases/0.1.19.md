# 0.1.19 – sporing av kurslagring

Testutgave 25. september 2026. Den nye loggen viser fortsatt PHP-stopp etter 120 sekunder og ventende databaseskriving ved Avadas cache. Denne utgaven gir et avgrenset spor som knytter RegiNor-lagringen til riktig databaseforbindelse. **Produksjonsfeilen er ikke bekreftet løst.**

## Endringer

- Valgfri diagnostikk rundt kurslås, transaksjon, metadata, hver kursstatus, commit/rollback og cacheopprydding. Operasjons-ID, objekt-ID, nettsteds-ID, tidsbruk og eksisterende databaseforbindelse kan sammenholdes med hostens måling av aktive blokkeringer.
- Sporingen er avslått som standard og kan begrenses til ett nettsted. Den utfører ingen ekstra SQL-kall og logger ingen kursbeskrivelser, navn, innsendte data, SQL eller unntaksmeldinger.
- Feilpunkt registreres før opprydding. En shutdown-handler forsøker å bevare siste trinn ved PHP-fatalfeil/uventet avslutning; en drept prosess kan ikke garanteres å logge.
- Navn på cron-intervaller oversettes først etter `init`, slik at tidlige oppslag fra andre utvidelser ikke utløser RegiNors oversettelsesvarsel. Intervallene finnes fortsatt før `init`.

Rettigheter, versjonskontroll og samlet transaksjon beholdes. Ingen produksjonsinnstillinger eller køer er endret. Automatisk cron-testing er fortsatt på vent.

## Ett kontrollert forsøk

Installer ZIP-en. Legg følgende i `wp-config.php` før WordPress lastes (endre eventuelle eksisterende definisjoner):

```php
define('RNL_TRACE_MUTATIONS', true);
define('RNL_TRACE_SITE_ID', 19);
```

Bruk eksisterende PHP-/WordPress-feillogg. Last periodeoversikten på nytt og kontroller faktisk status. Dersom perioden fortsatt er publisert, gjør ett «Til kladd»-forsøk, helst mens host undersøker aktive låseventinger. Samle linjene med `RNL-MUTATION` og samme `trace_id`, samt fatalfeilen. Slå sporingen av igjen etterpå.

[Full fremgangsmåte og tolkning av trinn](../HOSTING-DATABASEKONTROLL.md#avgrenset-lagringsspor-fra-0119). [Loggfunn](../FEILSOKING-KLADD-OG-TEC.md#ny-kritisk-feil--24-september-21582205-utc).

## Verifikasjon

- Composer-kontroll: 152 PHP-filer syntakskontrollert, 230 tester / 565 assertions. Lokal Composer på PHP 8.5 skriver eksisterende deprecation-varsler; kontrollen består.
- Ny diagnostikkprøve: samme forbindelse som `CONNECTION_ID()`, ingen ekstra SQL, ett spor ved nøsting, riktige feilpunkter, vellykket lagring og rollback. Kjører de eksisterende 92 arbeidsflytkontrollene med diagnostikk aktivert.
- Arbeidsflyt også kjørt uten diagnostikk: 92 kontroller. Lagring: 65. HTTP: 43. WordPress-oppstart og oversettelsesregresjon består. POT er regenerert.
- Tidligere i samme arbeidsøkt bestod admin 91, kapasitet 39 og TEC 102 for oversettelsesrettingen. Disse er ikke kjørt på nytt etter tillegg av lagringssporing. Offentlige HTTP-/frontend-, øvrige API- og analyseprøver er ikke kjørt på nytt for denne avgrensede diagnoseendringen.
- ZIP-integritet og samsvar med alle 125 runtime-filer er kontrollert. Testdata og logger er ikke pakket. Faktisk Avada/TEC Pro/WPML/Sucuri/Wordfence/hosting og ny produksjonsprøve gjenstår.
